# AI推理能力基准：具有深刻数学背景的可合成问题类别

## 摘要

本文档提出了一系列用于评测先进人工智能（特别是大型语言模型）在符号推理、抽象结构理解和算法执行方面能力的问题类别。这些问题类别的设计旨在超越传统的自然语言理解和知识问答，通过提供形式化、可批量生成且具有深刻数学背景的任务，来系统性地衡量AI的逻辑演绎和计算能力。每个任务类别都遵循统一的设计原则，确保了问题的客观性、可扩展性和可验证性。

## 1. 核心设计原则

所有问题类别均遵循以下五个核心原则：

1.  **形式化输入 (Formal Input):** 问题可以被无歧义地表示为结构化数据（如JSON）或标准化的文本格式，便于机器解析。
2.  **确定性答案 (Deterministic Answer):** 每个问题都有一个唯一的、可通过算法验证的正确答案（例如：布尔值、整数、列表）。
3.  **可伸缩难度 (Scalable Difficulty):** 问题的复杂性可以通过改变输入参数（如对象的大小、数量或结构复杂度）进行调整，以适应不同能力的模型。
4.  **批量生成 (Batch Generation):** 存在明确的算法或框架，可以程序化地生成大规模的问题实例及其对应的标准答案。
5.  **深刻背景 (Profound Background):** 每个问题都源自一个成熟的数学或计算机科学分支，其解决过程不仅仅是表面计算，而是对核心概念的体现。

## 2. 任务类别详解

### 任务类别 1: 群论 - 结构性质判定

*   **领域:** 抽象代数 (Abstract Algebra)
*   **核心思想:** 根据有限群的表示（凯莱表或生成元），判断其是否具备某种代数结构性质。
*   **具体问题:**
    *   `IsSimple`: 判断群是否为单群（没有非平凡正规子群）。
    *   `IsAbelian`: 判断群是否为交换群（阿贝尔群）。
    *   `IsCyclic`: 判断群是否为循环群。
    *   `Center`: 计算群的中心（与所有元素都交换的元素构成的子群）。
*   **输入格式:**
    *   **`cayley_table`:** 一个 `n x n` 的整数矩阵，其中元素从 `0` 到 `n-1` 编号。
    *   **`permutation_generators`:** 一个置换列表，每个置换是一个数组，作用于 `{0, 1, ..., n-1}`。
*   **输出格式:**
    *   对于判定问题：`"Yes"` 或 `"No"`。
    *   对于计算问题：一个整数列表。
*   **示例 (IsSimple):**
    *   **输入 (JSON):**
        ```json
        {
          "problem_id": "group_simple_001",
          "task": "IsSimple",
          "group_representation": {
            "type": "permutation_generators",
            "domain_size": 3,
            "generators": [
              [1, 2, 0],  // 置换 (0 1 2)
              [1, 0, 2]   // 置换 (0 1)
            ]
          }
        }
        ```
    *   **预期输出:**
        ```json
        {
          "problem_id": "group_simple_001",
          "answer": "No"
        }
        ```
        *解释: 该群为 S₃，其正规子群 A₃（由 `[1, 2, 0]` 生成）非平凡。*
*   **批量生成策略:** 使用 `GAP`, `SageMath` 等计算代数系统，可以系统地生成特定阶数的所有群或随机置换群，并使用内置函数计算其性质作为基准答案。
*   **数学背景:** 拉格朗日定理、西罗定理、正规子群、商群、有限单群分类。

### 任务类别 2: 自动机理论 - 语言性质判定

*   **领域:** 形式语言与计算理论 (Formal Languages & Theory of Computation)
*   **核心思想:** 分析由有限自动机（DFA/NFA）定义的正则语言的全局性质。
*   **具体问题:**
    *   `IsEmpty`: 判断自动机接受的语言是否为空。
    *   `IsUniversal`: 判断自动机是否接受所有可能的字符串 (`L(A) = Σ*`)。
    *   `IsEquivalent`: 给定两个DFA，判断它们是否接受相同的语言。
*   **输入格式:** 使用JSON描述自动机的五元组 `(Q, Σ, δ, q₀, F)`。
*   **输出格式:** `"Yes"` 或 `"No"`。
*   **示例 (IsUniversal):**
    *   **输入 (JSON):**
        ```json
        {
          "problem_id": "dfa_universal_001",
          "task": "IsUniversal",
          "automaton": {
            "states": ["q0", "q1"],
            "alphabet": ["a", "b"],
            "transitions": {
              "q0": {"a": "q1", "b": "q0"},
              "q1": {"a": "q0", "b": "q1"}
            },
            "start_state": "q0",
            "accept_states": ["q0"]
          }
        }
        ```
    *   **预期输出:**
        ```json
        {
          "problem_id": "dfa_universal_001",
          "answer": "No"
        }
        ```
        *解释: 该DFA接受所有包含偶数个 `a` 的字符串，并非字母表 `{a, b}` 上的所有字符串。*
*   **批量生成策略:** 随机生成状态转移图，或从正则表达式通过标准算法（Thompson构造、子集构造）生成DFA。通过对DFA进行补集、交集等操作可以构造出具有特定性质的复杂实例。
*   **数学背景:** Myhill-Nerode定理、正则语言的闭包性质、DFA最小化算法、图可达性算法。

### 任务类别 3: 计算拓扑学 - 不变量计算

*   **领域:** 代数拓扑 (Algebraic Topology)
*   **核心思想:** 从一个空间的离散组合表示（单纯复形）中，计算其内在的拓扑不变量。
*   **具体问题:**
    *   `BettiNumbers`: 计算空间的贝蒂数 `(b₀, b₁, b₂, ...)`，分别对应0维、1维、2维等不同维度的“洞”的数量。
    *   `EulerCharacteristic`: 计算欧拉示性数 (χ = V - E + F - ...)。
*   **输入格式:** 一个列表的列表，每个子列表代表一个单纯形（由顶点索引构成）。
*   **输出格式:** 一个整数列表。
*   **示例 (BettiNumbers):**
    *   **输入 (JSON):**
        ```json
        {
          "problem_id": "topo_betti_001",
          "task": "BettiNumbers",
          "simplicial_complex": [
            [0], [1], [2],      // 0-单纯形 (顶点)
            [0, 1], [1, 2], [2, 0] // 1-单纯形 (边)
          ]
        }
        ```
    *   **预期输出:**
        ```json
        {
          "problem_id": "topo_betti_001",
          "answer": [1, 1, 0]
        }
        ```
        *解释: 该单纯复形是一个空心三角形的边界。它有1个连通分量 (`b₀=1`)，1个一维的洞 (`b₁=1`)，没有二维的空腔 (`b₂=0`)。*
*   **批量生成策略:** 随机生成单纯复形（如Erdős-Rényi模型的推广），或对已知的拓扑流形（如球面、环面）进行三角剖分。使用 `Gudhi`, `Dionysus` 等库计算同调群以获得基准答案。
*   **数学背景:** 同调论、单纯复形、链复形、边界算子、欧拉-庞加莱公式。

### 任务类别 4: 数理逻辑 - 公式性质判定

*   **领域:** 逻辑与计算复杂性 (Logic & Computational Complexity)
*   **核心思想:** 判断一个逻辑公式的语义属性，如可满足性或永真性。
*   **具体问题:**
    *   `SAT`: 给定一个合取范式 (CNF) 的命题逻辑公式，判断其是否可满足。
    *   `Tautology`: 判断一个命题逻辑公式是否为永真式。
    *   `ModelCheck`: 给定一个有限的一阶逻辑模型和句子，判断该句子在模型中是否为真。
*   **输入格式:**
    *   **CNF:** 整数列表的列表，正数表示变量，负数表示其否定。
    *   **通用公式:** LISP风格的S-表达式字符串。
*   **输出格式:** `"SATISFIABLE" / "UNSATISFIABLE"` 或 `"TAUTOLOGY" / "NOT A TAUTOLOGY"`。
*   **示例 (SAT):**
    *   **输入 (JSON):**
        ```json
        {
          "problem_id": "logic_sat_001",
          "task": "SAT",
          "formula_cnf": [
            [1, -2, 3],
            [-1, 2],
            [-3]
          ]
        }
        ```
        *公式: (x₁ ∨ ¬x₂ ∨ x₃) ∧ (¬x₁ ∨ x₂) ∧ (¬x₃)*
    *   **预期输出:**
        ```json
        {
          "problem_id": "logic_sat_001",
          "answer": "SATISFIABLE"
        }
        ```
        *解释: 一组满足赋值为：x₁=True, x₂=True, x₃=False。*
*   **批量生成策略:** 使用标准的随机k-SAT生成器，通过调整变量数与子句数的比率来控制难度。也可以将其他NP完备问题（如哈密顿回路）编码为SAT实例。使用成熟的SAT求解器（如MiniSAT, Z3）来获取基准答案。
*   **数学背景:** 命题逻辑、布尔代数、计算复杂性理论 (P vs NP)、Cook-Levin定理。

## 3. 统一生成框架

为了实现这些问题的批量合成，我们提出一个三阶段框架：

1.  **生成器 (Generator):** 根据指定的参数（如群的阶数、图的顶点数），调用底层数学库程序化地创建一个数学对象。
2.  **求解器 (Solver):** 使用同一数学库中的权威算法或外部专用求解器，计算该对象的性质，得到标准答案。
3.  **格式化器 (Formatter):** 将生成的数学对象和标准答案打包成统一的、对AI友好的格式（如前述JSON示例），并可以附加上自然语言描述的问题。

该框架确保了数据集的规模、质量和多样性，为训练和评测下一代AI的推理能力提供了坚实的基础。
