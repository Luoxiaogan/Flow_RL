# 训练评估系统说明文档

## 系统概述

本系统实现了大语言模型的高效训练和实时评估功能，主要特点：

1. **优化存储**: 仅保存模型权重，不保存优化器状态，将检查点大小从~60GB减少到~15GB
2. **并行评估**: 训练过程中自动对新检查点进行评估，实时监控模型性能
3. **灵活配置**: 支持Llama和Qwen两种模型，可配置损失掩码、评估间隔等参数
4. **分布式训练**: 使用DeepSpeed ZeRO-3优化，支持8卡并行训练

## 核心功能

### 1. 仅保存模型权重

#### 原理
- DeepSpeed ZeRO-3将8B参数模型分片到8个GPU上，每个GPU持有~1B参数
- 标准检查点包含：模型权重(~15GB) + 优化器状态(~45GB) = ~60GB
- 仅保存模型权重可减少75%的存储空间

#### 实现
```python
# src/train.py 中的自定义回调
class SaveModelCallback(TrainerCallback):
    """仅保存模型权重，不保存优化器状态"""
    def on_save(self, args, state, control, **kwargs):
        # 创建标记文件表示这是仅模型权重的检查点
        # DeepSpeed自动处理模型权重的收集和保存
```

#### 配置
```json
// configs/deepspeed_config_z3.json
{
    "checkpoint": {
        "load_optimizer_states": false,
        "load_lr_scheduler_states": false
    }
}
```

### 2. 实时评估系统

#### 评估指标
- **困惑度(Perplexity)**: 模型预测能力的主要指标，越低越好
- **平均损失(Loss)**: 训练目标函数值
- **Token统计**: 评估的总token数量

#### 评估流程
1. 后台启动训练进程
2. 定期扫描新的检查点
3. 使用独立GPU进行评估（避免干扰训练）
4. 保存评估结果到JSON文件
5. 生成评估报告

### 3. 损失掩码功能

只在assistant回复上计算损失，提高模型质量：

- **标准模式**: 在所有token上计算损失
- **掩码模式**: 仅在assistant回复token上计算损失
- **效果**: 模型更专注于生成高质量回复

## 使用方法

### 方法1：标准训练（仅保存模型）

```bash
# 使用默认配置（已启用仅保存模型）
bash run_finetune.sh

# 或指定模型类型
bash run_llama.sh   # Llama模型
bash run_qwen.sh    # Qwen模型
```

### 方法2：训练+实时评估

```bash
# 启动训练和评估系统
bash run_finetune_eval.sh

# 系统将：
# 1. 启动训练进程
# 2. 每30分钟评估新检查点
# 3. 生成评估报告
```

### 方法3：单独评估

```bash
# 评估指定检查点
python src/evaluation.py \
    --model_path /path/to/checkpoint \
    --eval_data /path/to/eval.jsonl \
    --model_type llama \
    --batch_size 4 \
    --use_loss_mask \
    --output_dir ./eval_results
```

## 常见问题

### Q1: 为什么要仅保存模型权重？

**A**: 优化器状态占用大量存储空间（约45GB），但只在恢复训练时需要。如果只做推理和评估，仅需要模型权重（约15GB）。

### Q2: 评估会影响训练速度吗？

**A**: 评估使用独立的GPU（默认GPU 7），不会影响主训练进程。评估间隔可配置，建议30-60分钟。

### Q3: 如何选择使用损失掩码？

**A**: 建议在指令微调时启用损失掩码，让模型专注于生成高质量回复。预训练或需要学习完整对话结构时可禁用。

### Q4: 检查点可以用于继续训练吗？

**A**: 仅模型权重的检查点不能直接继续训练（缺少优化器状态）。如需继续训练，请临时禁用`SAVE_ONLY_MODEL`选项。

### Q5: 如何监控训练进度？

**A**: 
- 查看训练日志: `tail -f [OUTPUT_DIR]/train.log`
- 查看评估日志: `tail -f [OUTPUT_DIR]/eval.log`
- WandB监控: 访问wandb.ai查看实时指标

## 最佳实践

1. **存储优化**
   - 生产环境始终启用`SAVE_ONLY_MODEL=true`
   - 定期清理旧检查点，保留最佳的3-5个

2. **评估策略**
   - 初期训练：每30分钟评估一次

3. **模型选择**
   - Llama: 通用任务，英文为主

4. **调试建议**
   - 先用小数据集测试配置
   - 确认GPU内存充足（每卡需要~40GB）
   - 检查数据格式是否正确

## 技术细节

### DeepSpeed ZeRO-3 工作原理

1. **模型分片**: 8B参数均匀分布到8个GPU
2. **通信优化**: 仅在需要时收集参数
3. **内存效率**: 每个GPU只存储1/8的模型
4. **保存流程**: 
   - 训练时：参数分散在各GPU
   - 保存时：收集所有分片到rank 0
   - 写入磁盘：完整模型约15GB

### 评估并行化

```
GPU 0-6: 训练进程（DeepSpeed分布式）
GPU 7: 评估进程（独立运行）
CPU: 监控和调度
```
