# ToolOrchestra Codebase Guide

## Project Overview

ToolOrchestra is a framework for training small orchestrator models (8B parameters) that coordinate the use of intelligent tools and specialized models. The trained **Orchestrator-8B** model achieves state-of-the-art results on benchmarks like HLE, FRAMES, and τ²-Bench by efficiently orchestrating:

- **Basic tools**: Web search, code interpreter
- **Specialized LLMs**: Math models, coding models
- **Generalist LLMs**: GPT-5, Claude Opus, Llama-Nemotron-Ultra

The training uses end-to-end reinforcement learning with outcome, efficiency, and preference rewards (GRPO algorithm).

## Key Components

### 1. LLM_CALL.py - LLM Interface

Central module for calling various LLM providers:

- **OpenAI/Azure**: GPT-4o, o3, o3-mini, GPT-5
- **Claude**: Opus, Sonnet (via NVIDIA proxy)
- **vLLM servers**: Qwen, Llama, DeepSeek models
- **NVIDIA API**: OSS models

Key function: `get_llm_response(model, messages, temperature, tools, ...)` - unified interface for all model types.

### 2. data_synthesis/ - Data Synthesis Pipeline

The notebook `run.ipynb` generates training data through:

1. **Schema Generation**: Generate database schemas using GPT-5
2. **Data Model Generation**: Convert schemas to Pydantic models
3. **Database Content Generation**: Populate databases with realistic entries
4. **Tool Generation**: Create domain-specific tool functions
5. **Task Generation**: Generate multi-step agentic tasks
6. **Task Evolution**: Evolve tasks to increase complexity

Prompts are stored in `prompts/`:
- `schema_prompt.txt`: Database schema generation
- `data_model_prompt.txt`: Pydantic model conversion
- `db_entry_prompt.txt`: Database content generation
- `tool_prompt.txt`: Tool function generation
- `task_prompt.txt`: Task generation
- `evolve_prompt.txt`: Task evolution/complexity enhancement

### 3. training/verl/ - RL Training Framework

Modified veRL framework for GRPO (Group Relative Policy Optimization):

- `protocol.py`: DataProto for data handling
- `trainer/`: Training loop implementations
- `workers/`: FSDP and Megatron distributed workers
- `models/`: Model implementations
- `utils/`: Utilities for tracking, device handling, etc.

### 4. training/rollout/ - τ²-bench Environment

Environment for multi-turn agent interactions:

- `tau2/run.py`: Main simulation runner
- `tau2/agent/llm_agent.py`: LLM-based agent implementation
- `tau2/domains/`: Domain environments (airline, bank, retail, telecom, etc.)
- `tau2/environment/`: Tool execution environment
- `tau2/evaluator/`: Reward computation

Each domain has:
- `data_model.py`: Pydantic models for domain entities
- `tools.py`: Domain-specific tool implementations
- `environment.py`: Environment setup

### 5. training/lead_agent/ - Agent Generation

`llm_agent/generation_quick3.py` contains:
- Tool calling logic for `enhance_reasoning`, `answer`, `search`
- Integration with vLLM servers and external APIs
- Code execution sandbox for reasoning enhancement
- Cost/latency tracking for efficiency rewards

### 6. training/recipe/ - Training Algorithms

- `algo/main_grpo_quick3.py`: Main GRPO training entry point
- `algo/grpo_ray_trainer_quick3.py`: Ray-based distributed GRPO trainer
- `dapo/`: DAPO algorithm implementation

### 7. training/tools.json - Orchestrator Tools

Three main tools available to the orchestrator:

1. **enhance_reasoning**: Code generation for intermediate reasoning
   - Models: reasoner-1/2/3 (different capability/cost tradeoffs)

2. **answer**: Final answer generation
   - Models: answer-1/2/3/4, answer-math-1/2

3. **search**: Information retrieval
   - Models: search-1/2/3

Each model has different pricing and latency characteristics used for efficiency rewards.

## Training Workflow

1. **Launch Services** (`resume_h100.py`):
   - Manages SLURM jobs for vLLM model servers
   - Configures model endpoints in `serve_train_tool_orchestra.json`
   - Launches training when all services are ready

2. **Training Loop** (`recipe/algo/`):
   - Initialize Ray cluster
   - Load model with FSDP/Megatron
   - Run GRPO iterations:
     - Generate rollouts using orchestrator
     - Compute rewards (outcome + efficiency + preference)
     - Update policy with advantage estimation

3. **Rollout** (`rollout/tau2/`):
   - Agent receives task
   - Orchestrator selects tools/models iteratively
   - Environment executes tool calls
   - Evaluator computes final reward

## Running Training

```bash
cd training
python resume_h100.py  # For SLURM-managed cluster
# Or directly:
python recipe/algo/main_grpo_quick3.py
```

## Common Development Tasks

- **Modify LLM calls**: Edit `get_llm_response()` in `LLM_CALL.py`
- **Add new tools**: Update `training/tools.json` and implement in `lead_agent/`
- **Add new domains**: Create domain folder in `training/rollout/tau2/domains/`
- **Adjust training config**: Modify `recipe/algo/config/grpo_trainer.yaml`
