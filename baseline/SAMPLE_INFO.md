# 📊 Benchmark样本数说明

## 各Benchmark可用样本数

根据`Processed_dataset`中的实际数据：

| Benchmark | 测试集样本数 | 说明 |
|-----------|-------------|------|
| **GSM8K** | 1319 | 数学推理问题，样本充足 |
| **MBPP** | 500 | Python编程基础题，样本充足 |
| **HumanEval** | 164 | Python函数实现，样本较少 |

## 样本数不足的处理

### 自动处理机制
```python
n_samples = min(requested_samples, available_samples)
```

系统会自动处理样本数不足的情况：
- 如果请求200个样本，但HumanEval只有164个
- 系统会使用全部164个样本
- 并显示警告信息

### 警告示例
```
⚠️ 警告: 请求200个样本，但只有164个可用
将使用所有164个样本
```

## 配置建议

### 1. 统一使用较少样本数（推荐）
```yaml
test:
  samples_per_benchmark: 150  # 所有benchmark都能满足
```

### 2. 分别配置（需要修改代码支持）
```yaml
test:
  samples_per_benchmark:
    gsm8k: 200
    mbpp: 200
    humaneval: 150
```

### 3. 使用全部样本
如果想使用全部可用样本，可以设置一个很大的数字：
```yaml
test:
  samples_per_benchmark: 9999  # 会自动限制到实际数量
```

## 统计显著性考虑

### 最小样本数建议
- **快速测试**: 10-20个样本
- **初步评估**: 50-100个样本
- **统计显著**: 150+个样本

### HumanEval的164个样本
- 对于统计测试是足够的
- 可以得出有意义的性能对比
- 不必担心样本数不足

## 实际运行示例

当配置为200个样本时：
```
[1/3] GSM8K
  从 1319 个样本中随机选择了 200 个

[2/3] MBPP
  从 500 个样本中随机选择了 200 个

[3/3] HumanEval
  ⚠️ 警告: 请求200个样本，但只有164个可用
  将使用所有164个样本
  从 164 个样本中随机选择了 164 个
```

## 总结

- 系统会**自动处理**样本数不足的情况
- 不会报错，会使用所有可用样本
- 会显示清晰的警告信息
- HumanEval的164个样本对于评估是足够的
