# AI 工作流生成与执行系统

这是一个先进的系统，旨在利用大型语言模型（LLM）自动生成、执行和验证用于解决复杂问题（如数学推理和代码生成）的AI工作流。系统采用模块化和可扩展的设计，将工作流的**生成**阶段与**执行/验证**阶段完全分离，并通过本次重构增强了逻辑的健壮性和模块的独立性。

## 系统架构

本系统由三个核心Python脚本、一套插件式的“基准处理器”（Benchmark Handlers）以及共享工具模块组成，共同协作完成任务。

### 核心组件

1.  **`master_runner.py` (总指挥)**
    *   **职责**: 作为最高级别的调度器，负责整个流程的控制。
    *   **工作方式**:
        1.  读取指定基准测试（Benchmark）的数据集总数，并创建随机抽样的任务列表。
        2.  将任务列表分成多个批次（Batch）。
        3.  **分阶段**处理每个批次：
            *   **阶段一 (生成)**: 调用 `workflow_generator.py`，为其分配当前批次的任务和**全局唯一的起始ID**，批量生成工作流文件。
            *   **阶段二 (执行)**: 在生成成功后，遍历新生成的工作流文件，逐个调用 `workflow_executor.py` 来执行和验证它们。

2.  **`workflow_generator.py` (工作流生成器)**
    *   **职责**: 专注于与LLM交互，生成工作流的Python代码。
    *   **工作方式**:
        1.  接收来自 `master_runner.py` 的一批任务（问题索引和起始ID）。
        2.  根据指定的 `benchmark` 名称，动态加载对应的 **Benchmark Handler**。
        3.  使用 Handler 从数据集中提取问题文本，并结合 `conditions.py` 中的模板构建出高度定制化的Prompt。
        4.  并行地向LLM API（例如，通义千问）发送请求。
        5.  解析LLM的响应，并保存两个文件，确保工作流ID在所有批次中都是唯一的：
            *   `<workflow_id>.py`: 只包含纯净的工作流逻辑代码。
            *   `<workflow_id>.meta.json`: 包含元数据（如benchmark名称、问题索引、数据集路径等），供执行器使用。

3.  **`workflow_executor.py` (工作流执行器)**
    *   **职责**: 专注于执行和验证**单个**已生成的工作流。
    *   **工作方式**:
        1.  接收一个工作流文件路径 (`--workflow-path`)作为输入。
        2.  读取该文件旁边的 `.meta.json` 文件以获取所有必要的上下文信息。
        3.  动态加载对应的 **Benchmark Handler**。
        4.  将完整的**问题数据字典**（而不仅仅是文本）传递给工作流实例，以支持更复杂的操作符。
        5.  使用 Handler 将工作流代码包装成一个完整的、可执行的脚本，并在受控环境中用 `exec()` 执行。
        6.  使用 Handler 的 `judge` 方法来评判输出结果的正确性。
        7.  将最终结果（成功、失败、错误类型等）追加写入到主工作区的 `execution_results.csv` 文件中。

### 插件与工具

1.  **Benchmark Handler (插件系统)**
    *   **位置**: `ScoreFlow/scripts/<benchmark_name>/handler.py`
    *   **基类**: 所有 Handler 都必须继承自 `ScoreFlow/scripts/base_handler.py` 中定义的 `BenchmarkHandler` 抽象类。
    *   **职责**: 封装所有与特定数据集相关的逻辑，是系统可扩展性的核心。
        *   `get_prompt_text()`: 定义如何从数据记录中提取问题文本。
        *   `get_verification_data()`: 获取用于验证的完整数据对象。
        *   `build_executable_script()`: 定义如何将工作流代码包装成可执行脚本。
        *   `judge()`: 定义该数据集的“正确性”标准。例如，对GSM8K是比较最终数值，对MBPP是运行单元测试。

2.  **共享工具 (Shared Utilities)**
    *   **位置**: `ScoreFlow/scripts/utils/`
    *   **职责**: 提供可被多个模块重用的底层功能，以避免循环依赖。
    *   **示例**: `code_executor.py` 包含 `unsafe_execute` 函数，它被 `mbpp/handler.py` 和 `mbpp/operator.py` 同时需要，通过移入 `utils` 实现了模块解耦。

## 如何使用

通过 `run_workflow_system.sh` 脚本来运行整个系统。

### 1. 安全设置 (首次使用)

为了安全起见，**不要将API密钥硬编码在脚本中**。请使用环境变量。
在您的终端中运行（将`sk-xxx`替换为您的真实密钥）：
```bash
export YOUR_API_KEY="sk-xxxxxxxxxxxxxxxxxxxxxxxx"
```

### 2. 准备工作

*   确保您的Python环境中已安装所有必要的依赖项（如 `openai`, `metagpt` 等）。
*   将您的数据集（如 `gsm8k/train.jsonl`, `mbpp/train.jsonl`）放置在项目中。推荐放在根目录下的 `data/` 文件夹内，方便管理。

### 3. 配置脚本

打开 `run_workflow_system.sh` 文件并进行配置。

#### a. 通用配置

这些参数在不同任务间通常保持不变。

*   `API_POOL` / `EXEC_LLM`: API配置。脚本已设置为从环境变量 `$YOUR_API_KEY` 读取密钥。您只需检查模型名称和 `base_url` 是否正确。
*   `WORKSPACE_PATH`: 总工作空间。所有生成的文件和结果都将保存在此目录下。
*   `LOG_LEVEL`: 日志级别 (`INFO`, `DEBUG` 等)。
*   `MAX_CONCURRENT_TASKS`: 生成器内部的并发API请求数。
*   `WORKFLOW_TIMEOUT`: 单个工作流执行的最长允许时间（秒），防止无限循环。

#### b. 任务配置

脚本中包含多个任务配置块（例如，GSM8K, MBPP）。**一次只能启用一个任务块**。通过注释 (`#`) 或取消注释来选择要运行的任务。

*   `BENCHMARK`: 任务的名称（必须与 `ScoreFlow/scripts/` 下的目录名匹配，例如 `gsm8k`, `mbpp`）。
*   `TOTAL_PROBLEMS`: 数据集中的问题总数，用于随机抽样。
*   `MIN_SAMPLE_SIZE` / `MAX_SAMPLE_SIZE`: 每个工作流的Prompt中包含的问题示例数量范围。
*   `BATCH_SIZE`: `master_runner.py` 每批次处理的工作流数量。
*   `DATASET_PATH`: **推荐使用相对路径**，例如 `./data/gsm8k/train.jsonl`，这使项目更具可移植性。
*   `TRAINING_DATA_OUTPUT`: （可选）用于SFT的训练数据将追加写入到此文件。

### 4. 运行系统

1.  赋予脚本执行权限（仅需一次）：
    ```bash
    chmod +x run_workflow_system.sh
    ```
2.  执行脚本：
    ```bash
    ./run_workflow_system.sh
    ```

系统将开始运行，并在终端中打印详细的日志信息。

## 输出文件结构

所有输出都位于您配置的 `WORKSPACE_PATH` 中。

```
<WORKSPACE_PATH>/
|
|-- generated_workflows/
|   |-- gsm8k/
|   |   |-- gsm8k_0.py         # 生成的纯工作流代码 (ID全局唯一)
|   |   |-- gsm8k_0.meta.json  # 对应的元数据
|   |   |-- gsm8k_1.py
|   |   |-- gsm8k_1.meta.json
|   |   `-- ...
|   |
|   `-- mbpp/
|       |-- mbpp_0.py
|       |-- mbpp_0.meta.json
|       `-- ...
|
|-- execution_results.csv      # 所有工作流的最终执行结果摘要
|
`-- training_data_gsm8k.jsonl  # (如果在.sh中配置) SFT训练数据
```

## 命令行参数详解

虽然推荐使用 `.sh` 脚本，但您也可以直接调用每个核心脚本。以下是主要参数的解释。

#### `master_runner.py`

| 参数 | 解释 |
| --- | --- |
| `--benchmark` | **必需**. 要运行的基准测试名称。 |
| `--total-problems`| **必需**. 数据集总数，用于抽样。 |
| `--dataset-path` | **必需**. 数据集文件的路径。 |
| `--batch-size` | 每批处理的工作流数量。 |
| `--api-pool` | API配置池（JSON字符串）。 |
| `--exec-llm` | 执行LLM的配置（JSON字符串）。 |
| `--workspace-path`| 工作空间路径。 |
| ... | 其他传递给子脚本的参数。 |

#### `workflow_generator.py`

| 参数 | 解释 |
| --- | --- |
| `--benchmark` | **必需**. 用于加载对应的Handler和Prompt。 |
| `--dataset-path`| **必需**. 数据集路径。 |
| `--generation-tasks`| **必需**. 以逗号分隔的任务索引字符串，例如 `"1_2,5_8_9"`。 |
| `--id-start-index`| **必需**. 生成工作流ID的起始数字，由 `master_runner.py` 提供以确保全局唯一。 |
| `--api-pool` | API配置池（JSON字符串）。 |
| `--workspace-path`| 工作空间路径。 |

#### `workflow_executor.py`

| 参数 | 解释 |
| --- | --- |
| `--workflow-path` | **必需**. 要执行的 `.py` 工作流文件的路径。 |
| `--exec-llm` | **必需**. 执行LLM的配置（JSON字符串）。 |
| `--workspace-path`| **必需**. 用于保存CSV结果的主工作区路径。 |
| `--workflow-timeout`| 工作流执行超时时间。 |
